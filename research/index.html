Content Opportunity Scoring:
Which Pages Should Be Reviewed First?

Musa Khalid Gaya  ·  September 2026  ·  github.com/MusaGaya
Abstract

Content teams reviewing thousands of pages face a prioritisation problem: which pages deserve attention first? This project builds a Content Opportunity Scoring model that ranks pages by their likelihood of being in decline, using observable search and content signals from a 22,301-row anonymised dataset. A Random Forest classifier trained on eight features — including impressions, CTR, content age and average position — was compared against a hand-written baseline rule using Precision@K on a client-grouped holdout split. The model achieved a Precision@50 of 0.480 versus the baseline's 0.300, a directional improvement suggesting that learned signal combinations can help prioritise content review queues more effectively than fixed rules. Results are observational and decision-support only — the model identifies pages sharing characteristics with currently declining pages, and does not predict future outcomes or guarantee that a content refresh will cause recovery.

01 — Introduction

The Problem

A content team managing thousands of pages cannot review everything. They need a principled way to decide where to spend their limited review capacity. Today, many teams use hand-written rules — flag pages that are old, flag pages with low CTR, flag pages that are declining — but these rules treat all signals equally and cannot learn from the data they sit on.

This project asks: can a learned model rank pages for content review more accurately than a fixed rule, using only observable search and content signals?

The output is a ranked priority queue — a tool that helps a human reviewer decide which page to open first. Every recommendation requires human judgment before any action is taken.

What Was Excluded and Why

Rows with missing values in any of the eight feature columns were dropped (30,000 → 22,301 rows). Product decision flags are not present in the dataset by design — they would create circular results if used as features. The trend_direction column was used only as the label source, never as a feature.

03 — Methodology

Methodology

Label Definition

The proxy label is is_declining_label = (trend_direction == "down"). This is a current-state proxy — it identifies pages currently in a declining trend, not a future-looking prediction. This is a known limitation discussed in the Limitations section.

Features

Eight observable signals, all knowable before any review decision is made:

impressions_90d      # total search impressions, 90-day window
avg_position        # average search ranking position
content_age_days    # how old the page is
ctr                 # click-through rate
word_count          # content length
days_since_last_update # staleness signal
sessions_90d        # GA4 sessions in 90-day window
engagement_rate     # session engagement metric

Baseline Rule

A weighted rule combining three normalised signals: staleness (40%), visibility (35%) and CTR gap (25%). This is the score the model must beat.

Model

Random Forest Classifier (100 trees, max depth 6, class_weight="balanced", random_state=42). Chosen because it handles non-linear signal combinations, produces continuous probabilities for ranking, and was the strongest performer in the starter pipeline benchmark.

Validation Design

Client-grouped holdout split: 80% of clients for training, 20% for testing. No client appears in both sets. This tests whether the model generalises to clients it has never seen — the honest real-world use case.

Leakage Checks

All eight features were confirmed knowable before any review decision is made. trend_direction and trend_pct were excluded from features. No product flags were used. No future-window data was used.

05 — Limitations

Limitations & Honest Framing

These results are directional and decision-support only. The model identifies pages that share characteristics with currently declining pages. It does not predict future traffic, and it cannot prove that a content refresh will cause recovery.

Proxy Label Weakness

The label is calculated from the same 90-day window as the features. The model is identifying current state, not predicting future outcomes. A stronger version would use a prior feature window to predict a future target window.

Dataset Scope

Results come from a 22,301-row anonymised starter slice with 32 clients. They may not generalise to the full 79-million-row warehouse or to client types not represented in this slice.

What This Cannot Claim

This work does not identify Google algorithm factors. It does not prove that refreshing a flagged page will cause it to recover. It does not make claims about any specific client, domain or URL.

06 — Ranked Recommendations

Content Action Playbook

Pages are assigned one of four action labels. Start at rank 1 and work down until review capacity is exhausted. The score is a priority signal, not a verdict.

Priority 1
Review Both
stale_and_low_ctr
Page is 180+ days old, still visible and has low CTR. Review content AND metadata.
Priority 2
Review Content
stale_visible_page
Page is 180+ days old and still receives 100+ impressions. Update the content.
Priority 3
Review Metadata
low_ctr_visible_page
Page has 500+ impressions but CTR below 0.5%. Rewrite title or meta description.
Priority 4
Monitor
monitor
Page does not meet any review threshold. Check again next cycle.

What Should Never Be Automated

Content deletion, redirects, canonical changes, or publishing rewritten content without human approval. This queue is a starting point for human review, not an automated publishing pipeline.
